\reportprelimsection{LIST OF ABBREVIATIONS AND DEFINITIONS}
\begin{itemize}
    \item BFS - Breadth First Search, a graph traversal algorithm that explores vertices by levels;
    \item DFS - Depth First Search, a graph traversal algorithm that explores one branch before backtracking;
    \item graph density - ratio between existing edges and the maximum possible number of edges;
    \item KB - kilobytes;
    \item ms - milliseconds;
    \item traversal - process of visiting reachable vertices in a graph.
\end{itemize}

\reportintroduction
Depth First Search and Breadth First Search are two fundamental graph traversal algorithms. Both determine which vertices are reachable from a starting point, but they explore the graph in different ways. DFS follows a branch as deeply as possible before backtracking, while BFS explores the graph level by level.

These traversal strategies are important because they form the basis for many other graph algorithms. In practice, their empirical behavior depends not only on the number of vertices, but also on the number of edges, on graph density, and on the implementation choices used in the program.

\reportlabel{Theoretical Notes}
An alternative to mathematical analysis of complexity is empirical analysis. This may be useful for obtaining preliminary information on the complexity class of an algorithm, for comparing the efficiency of several algorithms that solve the same problem, and for observing the practical effect of implementation details on a particular computer \cite{gfg-bfs,gfg-dfs}.

In the empirical analysis of an algorithm, the following steps are usually followed: the purpose of the analysis is established; the efficiency metric is selected; the properties of the input data are defined; the algorithms are implemented; multiple input sets are generated; the program is executed for each input set; the obtained data are analyzed and represented graphically.

Both DFS and BFS have theoretical time complexity \(O(V + E)\) when the graph is represented through adjacency lists. Even so, the practical running time depends strongly on the number of edges, on the graph topology, and on the internal data structures used by the implementation \cite{gfg-bfs,gfg-dfs,yt}.

The comparison metrics chosen for the laboratory were:

    \item execution time in milliseconds;
    \item peak memory usage in kilobytes;
    \item number of visited vertices;
    \item success rate of the execution.
\end{itemize}

\reportlabel{Input Format}
The laboratory used two complementary styles of graph generation:
\begin{itemize}[leftmargin=1.25cm]
    \item graphs classified by fill percentage, from \(0\%\) to \(100\%\);
    \item graphs classified by topology, such as tree, complete graph, bipartite graph, cyclic graph, wheel graph, grid-planar graph, and disconnected graph.
\end{itemize}

For the base density program, representative sizes of 10, 50, 100, and 200 vertices were used. For the optimized topology program, sizes up to 1000 vertices were included in order to observe the scaling behavior more clearly.

\reportmainsection{IMPLEMENTATION}

\tocsubsection{Depth First Search}
The DFS implementation was prepared in both base and optimized forms. The base form uses simpler list-based structures, while the optimized form uses more suitable containers and membership tests. DFS explores one branch of the graph as deeply as possible before backtracking.

\reportlabel{Algorithm Description}

The DFS method follows the idea shown in the next pseudocode.

\begin{lstlisting}
DFS(graph, start):
    mark start as visited
    push start on stack
    while stack is not empty:
        node = pop stack
        for each neighbor of node:
            if neighbor is not visited:
                mark neighbor as visited
                push neighbor on stack
\end{lstlisting}

\reportlabel{Implementation}

The project contains both a classic and an optimized DFS implementation in the \texttt{Lab3} folder, and these were benchmarked against multiple graph families \cite{repo}.

\tocsubsection{Breadth First Search}
The BFS implementation uses queue-based traversal. It visits all neighbors on the current level before moving to the next depth level, which makes it suitable for shortest paths in unweighted graphs.

\reportlabel{Algorithm Description}

The BFS method follows the idea shown in the next pseudocode.

\begin{lstlisting}
BFS(graph, start):
    mark start as visited
    enqueue start
    while queue is not empty:
        node = dequeue queue
        for each neighbor of node:
            if neighbor is not visited:
                mark neighbor as visited
                enqueue neighbor
\end{lstlisting}

\reportlabel{Implementation}

The optimized BFS variant uses efficient queue operations and fast visited checks. The corresponding benchmark scripts compare it with DFS over both density-based and topology-based inputs.

\reportlabel{Conclusion}

BFS proved to be the best average performer among the optimized variants in the generated Lab 3 summaries. It remained especially effective on sparse topologies such as trees and grid-planar graphs, while its running time increased substantially on complete graphs because of the much larger edge set.

\reportunnumberedsection{CONCLUSION}
The performed experiments confirm that both DFS and BFS follow the theoretical \(O(V + E)\) tendency, but their practical behavior is strongly influenced by graph density, topology, and implementation details. Sparse structures such as trees and grid graphs remain inexpensive, while complete and near-complete graphs increase the cost considerably.

The four-version organization of the laboratory was useful because it separated two ideas of classification: percentage of fill and graph topology. This produced a clearer empirical analysis than a single benchmark setup would have provided. Overall, BFS was the fastest average optimized variant, while DFS was more sensitive to the structure of the graph and to the choice of data structures used internally.
